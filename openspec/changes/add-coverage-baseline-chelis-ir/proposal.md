# Proposal: add-coverage-baseline-chelis-ir

## Why

`chelis-ir` is 36k lines across 18 files, and 46 integration test binaries target it, but nobody knows which lines those binaries reach. The two files that matter most are the least understood: `lower.rs` is 11k lines and is the largest single file in the repository, and `eval.rs` is the bit-parity oracle for the C backend (chelis#770). An unreached lowering arm is a silent defect, because a lowering arm with no test emits wrong IR and no oracle objects. This change measures reach once, records it, and makes the number reproducible.

The measurement is also a prerequisite. Mutation testing and property testing are both expensive to point at a 36k-line crate without knowing which regions the existing suite already covers. Coverage data is the cheapest artifact that aims the later investment.

## What Changes

- New `scripts/coverage.py`: a stdlib-first Python 3.11+ wrapper over `cargo llvm-cov` that measures one named workspace package, emits a region-coverage summary per file, and writes machine-readable output to a gitignored path. Python, not shell, per the repository automation policy.
- New `scripts/coverage_baseline_chelis_ir.json`: a committed, hand-curated baseline snapshot of per-file region coverage for `chelis-ir`. It follows the discipline already established by `scripts/test_timing_baseline.json` — explicitly regenerated by a maintainer, never auto-updated on merge.
- New `scripts/test_coverage.py`: the unit-test oracle for the wrapper. It is discovered by the existing `python -m unittest discover -s scripts -p 'test_*.py'` step in the `lint-and-unit` job, so it needs no new gate wiring.
- New `.github/workflows/coverage.yml`: `workflow_dispatch` plus a weekly schedule. It never runs on `pull_request`, is not a required status check, and cannot block a merge. It must be added to `NON_GATE_WORKFLOWS` in `scripts/test_gate.py`, because `test_all_workflow_files_are_scope_classified` fails on any unclassified workflow file.
- New `docs/coverage_setup.md`: the runbook for local use, toolchain installation, and baseline regeneration, mirroring `docs/smt_build_setup.md`.
- The wrapper SHALL fail loudly and non-zero on a missing `cargo-llvm-cov`, an unknown package name, or a malformed baseline. It SHALL NOT degrade to reporting zero coverage, which would read as a catastrophic regression rather than a broken tool.

### Non-Goals

- **No coverage threshold, and no gate.** This change introduces no minimum percentage, no ratchet, and no merge blocker. A baseline that gates merges converts every honest refactor into a baseline fight; that argument must be made separately if it is ever wanted.
- **No workspace-wide coverage.** Instrumented builds roughly double `target/`, and the Linux runners already strip debuginfo and reclaim 25-30 GB to avoid the mid-link failure recorded in chelis#392. Scope is `-p chelis-ir` only.
- **No product behavior change.** Compiler, runtime, CLI, backend, package, and generated-code behavior are untouched. This is a contributor-process change.
- **No `spec/**` change.** No normative specification is modified, and no existing contract is weakened.
- **Not spec coverage.** `spec/design/spec_provenance.md` owns coverage authority in the atom-lifecycle and spec-provenance sense. This change measures LLVM source-region coverage of Rust code. The two are unrelated, and this change claims no authority over the former.

## Capabilities

### New Capabilities

- `coverage-baseline`: what the coverage wrapper measures, where it writes, how the committed baseline is regenerated and what authority it carries (advisory, never gating), and the fail-closed behavior required when the toolchain or inputs are broken.

### Modified Capabilities

None. No existing requirement changes.

## Impact

- `scripts/coverage.py` — new wrapper; resolves the package, invokes `cargo llvm-cov`, parses LCOV, renders the per-file summary.
- `scripts/test_coverage.py` — new unit tests; the authoritative acceptance oracle for this change.
- `scripts/coverage_baseline_chelis_ir.json` — new committed baseline.
- `scripts/test_gate.py` — `NON_GATE_WORKFLOWS` gains `coverage.yml`; without this the existing scope-classification test fails.
- `.github/workflows/coverage.yml` — new non-required workflow, dispatch plus weekly schedule.
- `.gitignore` — ignore the raw `cargo llvm-cov` output directory.
- `docs/coverage_setup.md`, `AGENTS.md` — runbook and a pointer to it.
- `CHANGELOG.md` — contributor-tooling entry.
- No crate under `crates/` is modified.
