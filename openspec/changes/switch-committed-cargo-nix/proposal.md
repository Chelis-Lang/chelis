## Why

The Nix package path generated the crate2nix graph with `generatedCargoNix` and import-from-derivation on every evaluation. IFD builds the generator before crate scheduling starts, so it serially gates every evaluating job, defeats Nix evaluation caching, and forces `allow-import-from-derivation`.

The `committed-graph` crate2nix profile removes IFD: Nix imports a tracked `Cargo.nix`. Regeneration then needs a crate2nix binary, which the ecosystem already pins in the shared ci repo. Rather than pin crate2nix a second time in this flake, the Devenv shell composes the shared ci consumer module (devenv polyrepo compose pattern) and consumes crate2nix — and OpenSpec — from `config.outputs`, so both tools have one ecosystem pin.

## What Changes

- Commit a `Cargo.nix` generated by crate2nix 0.15.0 with `generate --no-default-features --features chelis-cli/smt`.
- Replace the `generatedCargoNix` import-from-derivation with `import (root + "/Cargo.nix")`; drop `nixConfig.allow-import-from-derivation`.
- Flip the native `crate2nixCommittedGraph` check to require the committed graph, its banner, and the required workspace members.
- Compose the shared ci consumer module through `devenv.yaml` (a `ci` input plus `ci/devenv/consumer`); expose `config.outputs.crate2nix` and `config.outputs.openspec`.
- Add a `regenerate-crate2nix` Devenv command (backed by `scripts/regenerate_cargo_nix.py`) that refreshes or `--check`s the committed graph with `config.outputs.crate2nix`; run the `--check` as a Devenv smoke task.
- Remove the standalone crate2nix flake input, the `regenerate-crate2nix` flake app, and `nix/regenerate.nix`.
- Replace the independently pinned `openspecPinned` build with `config.outputs.openspec`.
- Rewrite the flake-contract, gate, and devenv-composition tests for the committed graph and the composed tools, with positive and negative parity.
- Do not change compiler, runtime, CLI, backend, language, or generated-code behavior; do not change public package names, the app product surface, or artifact layouts.

## Capabilities

### Modified Capabilities

- `nix-package-outputs`: Rust packages import a pinned committed crate2nix graph without import-from-derivation.
- `cross-platform-devenv`: the Devenv shell composes crate2nix and OpenSpec from the shared ci consumer module and owns the committed-graph freshness check.

## Impact

The change affects the flake, the shared Nix package helpers, the native check set, the native Nix CI jobs, the Devenv shell composition, and the flake-contract, gate, and devenv tests, plus the committed `Cargo.nix`.

The shared ci repo gains the profile-free consumer module (`devenv/consumer`) and one pins source (`devenv/shared/pins.nix`); it must land before this repository can reference `github:Chelis-Lang/ci`. This supersedes the crate2nix approach sketched in `add-devenv-rust-workspace-outputs`.
