# Chelis-Native Testing Infrastructure — Plan Update

## Summary

Add first-class testing to Chelis: a `Std.Test` module, a `chelis test` CLI command, and a convention for reef packages to include Chelis-language tests. Python test harnesses remain ONLY for cross-language parity verification (Nautilus vs scipy, Coral vs pandas). Everything else — unit tests, property tests, integration tests, smoke tests — is written in Chelis and run via `chelis test`.

This is a Phase 3 item. It requires the Bug 9 fix (eval hangs on reef imports) and fast `chelis eval` with package-aware imports as prerequisites.

---

## What Gets Built

### `Std.Test` module (in chelis-std)

Core assertion functions:

```chelis
-- Equality
def assert_eq(actual: f32, expected: f32, label: String) -> () ! { Test }
def assert_eq_int(actual: int64, expected: int64, label: String) -> () ! { Test }
def assert_eq_bool(actual: bool, expected: bool, label: String) -> () ! { Test }
def assert_eq_string(actual: String, expected: String, label: String) -> () ! { Test }

-- Approximate equality (for floating point)
def assert_close(actual: f32, expected: f32, tol: f32, label: String) -> () ! { Test }
def assert_close_tensor(actual: tensor[n, f32], expected: tensor[n, f32], tol: f32, label: String) -> () ! { Test }

-- Boolean
def assert_true(cond: bool, label: String) -> () ! { Test }
def assert_false(cond: bool, label: String) -> () ! { Test }

-- Tensor shape / properties
def assert_shape(t: tensor[n, f32], expected_n: int64, label: String) -> () ! { Test }

-- Failure (unconditional)
def fail(msg: String) -> () ! { Test }
```

The `Test` effect is a new algebraic effect. Assertion functions perform the `Test` effect. The `chelis test` CLI command handles `Test` by collecting pass/fail results. This means:

- Test assertions are type-tracked. A function with `! { Test }` in its signature is a test function. A function without it is production code. You can't accidentally leave assertions in production code — the effect propagates.
- Test handlers are composable. A custom test runner could handle `Test` differently (e.g., collect results into a data structure for reporting, or fail-fast on first assertion failure).

If the `Test` effect adds too much complexity to the initial implementation, the simpler alternative is: assertion functions are regular functions that call a runtime builtin (`chelis_test_assert`) which the CLI intercepts. The effect-based design is cleaner but not mandatory for v1.

### `chelis test` CLI command

```bash
chelis test                     # discover and run all test files in tests/
chelis test tests/frame.ch      # run a specific test file
chelis test tests/ --filter erf # run only tests whose names contain "erf"
```

Discovery convention: test files live in `tests/*.ch` (or `tests/**/*.ch` for subdirectories). Each test file contains zero or more `def test_*()` functions. The CLI discovers test files, evaluates each via the evaluator (not build→gcc→link→run), calls every `test_*` function, and reports results.

Output format:

```
tests/special.ch
  test_erf_symmetry ............ PASS
  test_erf_bounds .............. PASS
  test_erf_large_input ......... PASS

tests/linalg.ch
  test_lu_solve_2x2 ........... PASS
  test_qr_orthogonality ....... PASS
  test_svd_reconstruction ..... FAIL (assert_close: expected 3.0, got 3.0012, tol 1e-4)

5 passed, 1 failed
```

The CLI exits 0 if all tests pass, 1 if any fail. CI integrates trivially.

### Test file convention for reef packages

Every reef package includes a `tests/` directory with `.ch` test files:

```
chelis-lang/nautilus/
├── src/
│   ├── special.ch
│   ├── linalg.ch
│   └── ...
├── tests/
│   ├── special.ch          # Chelis-native tests for Special
│   ├── linalg.ch           # Chelis-native tests for LinAlg
│   ├── distributions.ch    # Chelis-native tests for Distributions
│   └── ...
├── scripts/
│   └── gen_goldens.py      # Python — ONLY for scipy parity fixtures
└── parity/
    └── run_parity.py       # Python — ONLY for scipy golden comparison
```

The `tests/` directory contains pure Chelis tests. The `parity/` directory (renamed from `tests/` for clarity) contains Python scripts that compare against external oracles (scipy, pandas). CI runs both:

```yaml
- run: chelis test tests/           # Chelis-native tests
- run: python parity/run_parity.py  # Python parity checks (scipy/pandas only)
```

## What Changes in Existing Repos

### Nautilus

**Move to Chelis-native tests for everything except scipy parity.**

Currently, `tests/run_numeric_tests.py` does everything: compiles Chelis code into C, links against the runtime, runs the binary, compares output against golden JSON fixtures generated by `scripts/gen_goldens.py` (which calls scipy/numpy).

After the migration:

**Stays in Python (`parity/`):**
- `gen_goldens.py` — generates scipy/numpy reference values (golden fixtures)
- `run_parity.py` — compiles Chelis test programs, runs them, compares output against golden fixtures. This is the only path that invokes `chelis build` + gcc + link + run, because it needs to compare Chelis runtime output against scipy values.

**Moves to Chelis (`tests/`):**
- Internal correctness tests (erf symmetry, gamma reflection formula, bessel recurrence relations, lu_solve on known small matrices, QR orthogonality, SVD reconstruction) — these don't need scipy. They verify mathematical identities that are true by definition.
- Edge case tests (erf at 0, gamma at 1, bessel at 0) — these check known exact values, not scipy output.
- Property tests (output range checks, monotonicity, sign constraints) — `assert_true(lt(erf(x), 1.0))` doesn't need scipy.
- Smoke tests (every exported function is callable with valid input and doesn't crash) — currently in `apismoke.ch`, extend with assertions.
- Negative tests (wrong input dimensions, wrong types) — currently implicit in `chelis check`, make explicit with `assert_true` on expected behavior.

**Example migration — `tests/special.ch`:**

```chelis
import Nautilus.Special (erf, erfinv, gamma, lgamma, beta)
import Std.Test (assert_close, assert_true, assert_eq)

-- Known exact values
def test_erf_zero() = assert_close(erf(0.0), 0.0, 1e-10, "erf(0) = 0")
def test_erf_large() = assert_close(erf(5.0), 1.0, 1e-6, "erf(5) ~ 1")
def test_gamma_one() = assert_close(gamma(1.0), 1.0, 1e-7, "gamma(1) = 1")
def test_gamma_half() = assert_close(gamma(0.5), 1.7724539, 1e-5, "gamma(0.5) = sqrt(pi)")

-- Mathematical identities (no scipy needed)
def test_erf_symmetry() = {
  x = 0.7
  assert_close(erf(x), neg(erf(neg(x))), 1e-7, "erf is odd")
}

def test_erf_erfinv_roundtrip() = {
  x = 0.3
  assert_close(erfinv(erf(x)), x, 1e-5, "erfinv(erf(x)) = x")
}

def test_gamma_recurrence() = {
  x = 3.5
  assert_close(gamma(add(x, 1.0)), mul(x, gamma(x)), 1e-4, "gamma(x+1) = x*gamma(x)")
}

def test_beta_symmetry() = {
  a = 2.0
  b = 3.0
  assert_close(beta(a, b), beta(b, a), 1e-7, "beta(a,b) = beta(b,a)")
}

-- Range / property checks
def test_erf_bounded() = {
  assert_true(lt(erf(0.5), 1.0), "erf(x) < 1 for finite x")
  assert_true(gt(erf(0.5), 0.0), "erf(x) > 0 for x > 0")
}

def test_gamma_positive() = {
  assert_true(gt(gamma(2.5), 0.0), "gamma positive for x > 0")
}
```

These tests run via `chelis test tests/special.ch`. No Python, no gcc, no linking, no golden files.

### Coral

**Move to Chelis-native tests for everything except pandas parity.**

Currently, the entire test suite is Python (golden generation via pandas, runtime comparison via compiled C). After migration:

**Stays in Python (`parity/`):**
- `gen_goldens.py` — generates pandas reference values
- `run_parity.py` — compiles Coral test programs, runs them, compares against pandas goldens

**Moves to Chelis (`tests/`):**
- Frame construction correctness (column types, row counts, column order)
- HAMT structural sharing (put/get/remove/contains/size)
- Filter logic (mask produces correct row subset)
- GroupBy aggregation on known small data (sum of [1,2,3] grouped by [a,a,b] = {a:3, b:3})
- Join key matching (inner join on known keys)
- Window rolling computations on known sequences
- NaN handling (is_nan, fill_nan, drop_nan on constructed tensors)
- Sort correctness (numeric sort on known order, string sort on known order)
- Reshape round-trips (pivot then melt recovers original)
- describe output on known data (mean of [1,2,3] = 2.0)

**Example — `tests/frame.ch`:**

```chelis
import Coral.Frame (from_pairs, get_float_col, filter, nrows, ncols, with_column, columns)
import Std.Test (assert_eq_int, assert_close_tensor, assert_true)

def test_construction() = {
  prices = to_tensor([100.0, 200.0, 300.0])
  df = from_pairs([("price", FloatCol(prices))])
  assert_eq_int(nrows(df), 3, "nrows = 3")
  assert_eq_int(ncols(df), 1, "ncols = 1")
}

def test_filter_by_mask() = {
  prices = to_tensor([100.0, 200.0, 300.0])
  df = from_pairs([("price", FloatCol(prices))])
  mask = gt(get_float_col(df, "price"), 150.0)
  filtered = filter(df, mask)
  assert_eq_int(nrows(filtered), 2, "filter keeps 2 rows")
}

def test_with_column_preserves_existing() = {
  prices = to_tensor([1.0, 2.0, 3.0])
  vols = to_tensor([0.1, 0.2, 0.3])
  df = from_pairs([("price", FloatCol(prices))])
  df2 = with_column(df, "vol", FloatCol(vols))
  assert_eq_int(ncols(df2), 2, "added column")
  -- Original price column unchanged
  assert_close_tensor(get_float_col(df2, "price"), prices, 1e-10, "price preserved")
}
```

### Shoals (and all future shells)

**Chelis-native tests from day one.** Python only for comparison against QuantLib or other external references, if needed. The default is `chelis test tests/`.

## Migration Scope for Existing Shells

### Nautilus migration estimate

Current `tests/run_numeric_tests.py` has ~1051 assertions. Rough split:

- **Moves to Chelis (~60-70%):** Known-value checks (erf(0)=0, gamma(1)=1), mathematical identity checks (symmetry, recurrence, reflection), range/property checks (bounded output, positivity, monotonicity), edge case checks (input at 0, large input, near-singularity), smoke checks (every function callable without crash), decomposition property checks (Q^T Q = I, A = QR, U Sigma V^T = A).

- **Stays in Python (~30-40%):** Scipy parity checks where the expected value comes from `scipy.special.erf(0.7)` or `scipy.linalg.lu_solve(A, b)` — anywhere the golden is generated by calling the Python library, not derived from a mathematical identity. Also the benchmark comparisons (performance, not correctness).

The migration is incremental: write the Chelis test file for a module, verify it passes via `chelis test`, then remove the corresponding assertions from the Python harness. The Python harness shrinks; it doesn't disappear.

### Coral migration estimate

Similar split. Frame construction tests, HAMT tests, filter/sort/groupby on known small data, NaN handling, reshape round-trips — all Chelis-native. Pandas column-value parity on large fixtures — stays in Python.

## Relationship to `chelis fuzz`

`chelis test` runs deterministic assertion-based tests. `chelis fuzz` (planned, deferred) generates random inputs and checks properties. They're complementary:

- `chelis test tests/special.ch` — "erf(0) = 0, erf is odd, erf is bounded"
- `chelis fuzz erf --property "output_in(-1,1)" --trials 10000` — "erf never produces output outside [-1,1] on 10k random inputs"

`Std.Test` is the foundation. `chelis fuzz` builds on it later. Both use the evaluator, both report pass/fail, both run from the CLI.
