# Effect-Guided Reproducibility Manifests

**Owner:** Shoals shell (`chelis-lang/shoals`), with a compiler-side pass in `chelis-lang/chelis`
**Depends on:** Effect system (shipped), `Random` effect tracking (shipped), Shoals (3l)
**Priority:** Medium. Ships alongside or shortly after Shoals.
**Status:** Design spec. Not actively developed.

---

## Problem

Monte Carlo reproducibility is a regulatory requirement in finance. When a model validation team reviews a pricing model, they need to verify that re-running the simulation with the same inputs produces identical results. Today this is managed by convention: "we set the seed at the top of the script." Nothing machine-verifies that no other source of randomness exists in the computation, that the seed actually covers all stochastic operations, or that a code change didn't introduce a new unseeded random call.

Chelis's effect system already tracks `Random` statically. A function typed `! { Random }` uses randomness; a function typed `! {}` (pure) does not. The `with seed(n) { ... }` handler makes randomness deterministic. The type system guarantees that a pure function has no randomness — not by convention, by construction.

The missing piece: extracting this information into a structured, human-readable, machine-checkable report.

## What a Reproducibility Manifest Is

A JSON (or structured text) report generated by the compiler for any Chelis program. It answers three questions:

1. **Where is randomness introduced?** Every expression annotated with `! { Random }` in the typed AST, with source location, the specific random operation (e.g., `uniform_like`, `normal_sample`, `dropout`), and the tensor shape of the random draw.

2. **How is each random operation handled?** For each random expression, which `with seed(n)` handler covers it, and what seed value. If a random expression is NOT covered by a handler (the `Random` effect propagates to the program's top-level type), the manifest flags it as "unseeded — non-reproducible."

3. **Is the computation fully reproducible?** A single boolean: are ALL random operations covered by seed handlers? If yes, the manifest certifies reproducibility. If no, it lists the uncovered operations.

## Implementation

### Compiler side (in `chelis-lang/chelis`)

A new compiler pass that walks the typed AST after type checking and effect inference. Not a new analysis — the information is already computed by the effect checker. The pass just extracts and formats it.

**New CLI command:**

```bash
chelis manifest mc_pricer.ch              # prints reproducibility manifest to stdout
chelis manifest mc_pricer.ch -o report.json  # writes to file
chelis manifest mc_pricer.ch --check       # exit 0 if reproducible, exit 1 if not
```

**Implementation location:** A new module in `crates/chelis-cli/` (or `crates/chelis-effects/`) that:

1. Takes the typed AST (output of the type checker)
2. Walks every expression node
3. For each node with `Random` in its effect row, records: source location, operation name, tensor shape
4. For each `with seed(n)` handler, records: source location, seed value, which random operations it covers (the handler's body)
5. Checks whether any random operation is not covered by a handler
6. Emits the structured report

**What it does NOT do:**
- No Lean proofs. The manifest is a compiler output, not a formal certificate. The Lean formalization (LaCaDiLE Theorem 3, effect correctness) proves that the effect system's tracking is sound — the manifest trusts that proof, it doesn't re-derive it.
- No runtime analysis. The manifest is computed statically from the typed AST. It doesn't run the program.
- No seed management. The manifest reports which seeds are used; it doesn't choose or validate them.

### Shoals side (in `chelis-lang/shoals`)

Shoals documentation and examples should demonstrate the manifest workflow:

```chelis
import Nautilus.Distributions (normal_sample)

def mc_price(spot: f32, vol: f32, rate: f32, T: f32, strike: f32, n_paths: int64) -> f32 ! { Random } = {
  -- generate paths
  template = const(0.0, [n_paths])
  z = normal_sample(template, 0.0, 1.0)
  s_T = mul(spot, exp(add(mul(sub(rate, div(mul(vol, vol), 2.0)), T), mul(mul(vol, sqrt(T)), z))))
  payoffs = max(sub(s_T, strike), 0.0)
  mul(exp(neg(mul(rate, T))), mean(payoffs))
}

def main() -> f32 = with seed(42) { mc_price(100.0, 0.2, 0.05, 1.0, 100.0, 100000) }
```

```bash
$ chelis manifest mc_pricer.ch --check
Reproducible: YES
Random operations: 1 (normal_sample at line 6)
All covered by: seed(42) at line 11
$ echo $?
0
```

The manifest becomes part of the Shoals test plan: every Shoals example program must pass `chelis manifest --check`.

### Integration with model validation workflows

The manifest is designed to be consumed by:

1. **CI pipelines:** `chelis manifest --check` as a CI gate. Fail the build if any random operation is unseeded.
2. **Model validation teams:** The JSON manifest is attached to model documentation alongside the LaTeX pricing formulas. The validator sees: "this model uses randomness at these points, all seeded, reproducibility certified."
3. **Octant (if built):** The notebook environment could show a "reproducibility status" indicator per cell — green if all random operations in the cell are seeded, red if not.

## Test Plan

- Positive: a fully-seeded program produces `"reproducible": true` with all operations listed
- Positive: a pure program (no Random effect at all) produces `"reproducible": true` with empty operation lists
- Negative: a program with an unseeded Random operation produces `"reproducible": false` with the operation listed in `unseeded_operations`
- Nested handlers: a program with multiple `with seed` blocks covering different operations correctly attributes each operation to its handler
- CLI: `--check` exits 0 for reproducible, 1 for not
- Format: output is valid JSON, parseable by standard tools

## What This Is NOT

- Not a formal proof of reproducibility. The manifest reports the effect system's analysis. The Lean formalization proves the analysis is sound. The manifest itself is a report, not a certificate.
- Not a seed recommendation system. It doesn't suggest which seeds to use or detect correlated seeds.
- Not a numerical reproducibility guarantee. Two runs with the same seed produce identical tensor values (the RNG is deterministic). But floating-point non-determinism from hardware (GPU reduction order, OpenMP thread scheduling) can still produce different results. The manifest guarantees algorithmic reproducibility (same code path), not bitwise reproducibility across hardware configurations. Document this caveat.
- Not a replacement for the effect system. The manifest consumes the effect system's output; it doesn't add new analysis capabilities.
