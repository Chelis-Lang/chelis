## 1. What Beacon is

Beacon is a bound-propagation prover for scalar numerical programs lowered to
the chelis RISC DAG. Given named scalar input ranges and one output-range
assertion, it proves the assertion with a certified enclosure, refutes it with
an Arb-certified counterexample point, or fails closed (`unknown` or
`unsupported`). All verdicts are statements about real-valued semantics and
carry a no-floating-point-roundoff note; a trusted `proved` is labeled
sound-over-approximation, never "proven, exact".

The engine's centerpiece is its certified checking core: the zonotope-guided,
Arb-leaf-certified lane, the Arb oracle lanes, and the structural-certificate
lane (section 3.1). That core is what ships today, what the 2026-07
experiments measured as the right architecture, and what the review
identified as the durable asset. Beacon's job in the wider proof stack is to
turn a proposed domain decomposition — its own, or one produced by a rented
external searcher — into a certified verdict. The organizing principle is
**own the checker, rent the searcher** (review §3): only claims carry trust,
so only the claim-checking kernel must be rigorous; search may be cheap,
uncertified, and even external, because a wrong search decision costs
efficiency, never soundness.

What Beacon is not, in the same present tense:

- **Not a tensor engine.** Input boxes are named scalars only, and the
  tensor/shape ops (`Sum`, `BlasMatmul`, `Reshape`, reductions, and the rest
  of that family) are rejected as `unsupported`. Whether Beacon grows
  tensor-aware abstract state or permanently delegates tensor goals is an
  open, ticketed decision:
  [beacon#52](https://github.com/Chelis-Lang/beacon/issues/52). Until it is
  decided, tensor-scale goals route to the external engine
  (alpha-beta-CROWN / auto_LiRPA) through the chelis dispatch seam
  (roadmap item 4.1).
- **No CROWN backward pass.** `src/linear_relaxation.rs` is private,
  affine-only groundwork, deliberately unreachable from every CLI, dispatch,
  and protocol surface, with tests enforcing that it stays hidden
  (`tests/cli.rs`). The decision record de-scopes it for the scalar fragment;
  see WI-B4 in section 5.
- **No ONNX front-end.** No Beacon code reads ONNX. Neural-network goals
  reach verification through the external engine, which consumes ONNX
  natively.
- **Not yet in production dispatch.** Beacon implements and tests the binary
  side of chelis #439's subprocess contract, but no chelis production code
  path registers Beacon as an engine; every dispatch to date originated in a
  test fixture. Chelis-side production wiring is roadmap item 1.1.
  Separately, Beacon parses WireDag schema versions 1, 2, and 3
  (`src/wire.rs`) and exposes the `--schema-versions` startup negotiation
  probe. Chelis WireDag v6 is exact-only and carries both the typed
  `Pad.fill` migration from chelis#878 and the dedicated `Count` operation
  from chelis#1287, so the advertised sets no longer overlap at the current
  producer version. That is an expected loud mismatch until Beacon adopts
  v6; it makes the chelis-side launcher negotiation and cross-repo gate in
  chelis#708 mandatory before production dispatch, not optional polish.

## 2. Scope and interfaces

Beacon's handoff is a subprocess dispatch contract plus a local library
adapter, both consuming the same request shape: serialized chelis `WireDag`
schema version 1, 2, or 3 bytes, an expected SHA-256 over the exact received
bytes, a chelis-resolved `root_index` root node id, named scalar input boxes,
and one output range. There is no normalization step between producer and
Beacon for hashing: no parse/reformat, key reordering, or re-serialization.
Beacon trusts chelis's `OutputRange.output -> root_index` resolution, requires
the value to be one of the DAG's root node ids, and treats the output name as
metadata. Unused input names are tolerated and soundly ignored; missing boxes
for evaluated `Load` names are invalid. The exact-byte convention is
validated against committed chelis-produced scalar bytes
(`tests/fixtures/chelis-wi3-scalar.wiredag.json`) with a negative mutation
suite (pretty-printing, key reordering, whitespace, and node-field reordering
all fail against the original hash).

The subprocess surface is `chelis-beacon dispatch --request <path-or->`
(inline base64 `WireDag` bytes plus `expected_dag_sha256`; the #439
`oracle: null | bool` selection plus the `"zonotope_verified"` string in
`arb-oracle` builds), `chelis-beacon protocol --json` (machine-readable
capabilities, supported schema versions, and the pinned erf-envelope hash),
and `--proof-bundle` sidecars for trusted `proved`/`refuted` outcomes only.
Hash mismatches, malformed requests, unsupported ops, and unresolved cases
fail closed as non-proof results.

Consumed upstream artifacts: the chelis WI-13 certified `erf` envelope,
vendored byte-for-byte at `data/erf_envelope.json` with its SHA-256 pinned;
and the Arb/FLINT oracle (master-plan WI-14) behind the `arb-oracle` feature.
The chelis-side graph-extraction seam (master WI-3) produces the DAGs Beacon
checks.

## 3. Architecture

### 3.1 Proof authorities

Three lanes can produce trusted results, and they are the engine's core:

1. **Arb oracle lanes** (`--oracle arb-point`, `arb-box`, `arb-split`, behind
   the `arb-oracle` feature). Certified 256-bit ball arithmetic; `proved`
   requires a sound enclosure contained in the goal assertion, and the split
   lane additionally requires complete leaf coverage with
   `leaves_unresolved=0`. Dispatch can emit `refuted` only for a
   deterministic Arb point witness whose certified enclosure lies wholly
   outside the asserted range.
2. **The zonotope-verified lane** (`check --oracle zonotope-verified`
   locally; dispatch selector `oracle: "zonotope_verified"`). The zonotope
   domain tracks linear dependence between variables and guides
   branch-and-bound splitting; the proof authority is independent Arb box
   containment on every final leaf, with proof-directed retry splitting.
   This lane is the centerpiece: it already has the shape the whole
   architecture is converging on — untrusted guidance proposing a
   decomposition, a trusted kernel certifying each leaf plus coverage — and
   section 3.2 extends exactly that shape.
3. **The structural-certificate lane** (`src/certificate.rs`). Exact real
   algebra over DAG SSA identity — `exact_cancellation_real`,
   `additive_ssa_residual_cancellation`, `bounded_relu_clamp_real` — emitting
   fully-trusted `proved` with zero Arb involvement, so it works in builds
   compiled without the Arb oracle. It is the only lane that can close
   zero-width identities: ball enclosures have width, certificates do not.
   Known wiring gap: the zonotope-verified mode returns early
   (`src/interval.rs:87`) and bypasses this lane, so the strongest search
   lane cannot prove the zero-width identities only certificates close.
   WI-H7 reinstates the routing.

Beneath the trusted lanes sits the abstract-domain ladder. The interval
domain has the broadest scalar op coverage and is loose (the dependency
problem); without an oracle it emits only `proved_oracle_unverified`, which
maps to untrusted. The zonotope domain is the tightness rung: it cancels
dependency analytically where intervals must split, at the measured cost law
of leaves proportional to 1/margin for relational claims resolved by
splitting alone. Its op coverage is currently narrower than the interval
lane's, which is backwards — the more rigorous lane should never be the
narrower one; closing that parity gap is roadmap item 2.7. Linear relaxation
is not on the shipped ladder (section 1).

### 3.2 The searcher/certifier restructure (WI-H1..H7): the completeness path

The decision record graduates the searcher/certifier split into Beacon
proper; the roadmap schedules it as its Phase 2. Summary (the decision record
is authoritative; the Python prototypes under
`experiments/abcrown-probe-2026-07-10/` and
`experiments/hard-claims-2026-07-13/` are the reference implementations):

- **WI-H1** — a fast, uncertified f64 interval searcher that proposes the
  split tree; output is a leaf list, not a verdict. Branching stays pluggable
  rather than clever: trial-split branching measured as a net wall-time loss
  at the current certifier cost ratio.
- **WI-H2** — leaf-only Arb certification: Arb runs once per final leaf,
  refines only on failure, and the trusted kernel verifies that the leaves
  tile the input box. Today's arb-split lane pays ball arithmetic on every
  explored box; the measurements say leaf-only certification is orders of
  magnitude cheaper with refinement rates of 0.2–2% (12% on the hardest 3-D
  relational claim).
- **WI-H3** — the hull-mask for undecided predicates in the searcher:
  bisection can never decide a predicate at its zero-crossing, so undecided
  `CmpLt` yields the sound {0, 1} hull; case-split only where it pays.
- **WI-H4** — the differential harness, Phase 2's collective acceptance
  oracle: the Rust port is pinned against the Python prototypes on the
  committed `bs_call_main.v0_8_recon.json` fixture.
- **WI-H5** — certified-lane portability
  ([beacon#49](https://github.com/Chelis-Lang/beacon/issues/49)):
  `scripts/arb_gate.py` hard-codes x86_64-linux and no macOS path for the
  certified lanes exists.
- **WI-H6** — an attack phase with certified refutation output: point
  sampling before splitting, Arb certification of the violating point, and a
  refutation channel distinct from "cannot prove". Measured: a false claim
  burned a 2M-evaluation split budget without finding its counterexample;
  81 samples plus one Arb evaluation refuted it in 13 ms, certified.
- **WI-H7** — certificate-lane routing: exact and zero-width claims route
  through the structural-certificate lane before ball evaluation in the
  restructured flow.

This restructure, plus the external-engine seam in section 4, is the plan's
completeness path. Beacon does not re-implement the CROWN search stack; it
becomes the trusted kernel that certifies decompositions, wherever they come
from.

### 3.3 Perturbed-branch policy

The pricer's `erf64` is an Abramowitz-Stegun approximation with
input-dependent branches lowered as `CmpLt` predicates — the same class of
object as a ReLU. What ships today is the arb-split predicate ladder:
literal threshold splits for `load < const` shapes (closed overlapping
cover; the strict comparison's runtime boundary belongs to the false
branch), certified-axis splitting when the predicate difference depends on
exactly one varying input axis (WI-B5b), and sound boolean full-box fallback
for multi-axis predicates. Forced predicates are never counted as
Arb-resolved comparisons, and `proved` still requires complete leaf coverage.

The 2026-07 experiments settled how much more policy this graph class needs:
none of the GenBaB kind. Input splitting with sound {0, 1} hulls for
undecided predicates was sufficient for every pricer goal tried — in the
external engine (stock input-split branch-and-bound, once a ~40-line custom
`Less` bound existed) and in the hybrid prototype alike. The searcher-side
form of this policy is WI-H3. GenBaB-style relaxation-guided branching is
not planned; it would presuppose the linear-relaxation domain that the
decision record de-scoped.

### 3.4 Special-function relaxations

Beacon consumes the chelis WI-13 certified `erf` envelope: saturation arms
outside the central box, a certified polynomial pair inside it. Direct
WireDag `erf` ops are bounded by evaluating every overlapped envelope segment
over the propagated argument interval; endpoint-only lookup is forbidden.
Central coefficients are parsed from C99 hex-float strings and pinned by
exact `f64` bit pattern, so the chelis/Beacon seam cannot hide sub-ULP
coefficient drift. Gappa-certified evidence maps to the
`special_function_certified` qualifier only on trusted `proved` reports. The
zonotope lane represents `erf` as a fresh node-local residual hull, never
correlated across joins. Runtime Sollya/Gappa generation is out of scope for
Beacon; the envelope-generator pipeline is roadmap item 5.1 (chelis-side).

The envelope is valid on [-300, 300]; behavior outside is currently
undocumented. Choosing the policy — document the range as a fail-closed
contract, or add true saturation arms with certified error at the joins — is
roadmap item 2.9.

The committed Black-Scholes graph open-codes `erf64`, so Beacon bounds it as
the graph it is; no special-function primitive layer is required for the
existing pricer.

### 3.5 Soundness testing

Two guardrails against an unsound transformer, both shipped:

- **Certified-point containment sampling.** Sample concrete points inside
  each input box, take each point's certified enclosure from the Arb point
  oracle, and assert that enclosure sits inside the abstract lane's
  over-approximated output. This does not prove a transformer sound, but it
  catches unsoundness empirically and cheaply. No nonlinear transformer
  enters a proof-capable lane without same-change-set Arb containment tests.
- **The Arb lanes as proof oracles.** For the current scalar surface, the
  arb-split lane is itself a proof oracle: closed midpoint leaf covers,
  containment per leaf, `leaves_unresolved=0`, `unknown` on budget
  exhaustion, `unsupported` on nonretryable ops.

### 3.6 Dispatch integration

Beacon-side, the #439 subprocess contract is implemented and tested: chelis
owns a thin `BeaconShim` that shells to the out-of-tree `chelis-beacon`
binary, and Beacon maps verdicts to chelis-shaped discharge metadata
(`sound_approximate` plus `sound_over_approximation` for Arb-backed `proved`;
everything else untrusted with no proof qualifier). Chelis-side, the
registration function exists but has no production caller, there is no
range-goal syntax, and `chelis prove --capabilities` currently overstates
availability — those are roadmap items 1.1, 1.2, and 0.2 respectively, all
chelis-side. The near-term dependency is roadmap 0.1: current WireDag v6
acceptance and version negotiation, without which the next chelis release
breaks every dispatch.

## 4. Validation and the division of labor with the external engine

Beacon draws on the CROWN / auto_LiRPA / GenBaB literature for its
relaxation ideas, but it does not port that stack; the reference verifiers
serve as a comparison baseline, not a blocker or a template.

The record, in order. A 2026-06-22 probe
(`docs/reference-verifier-feasibility-2026-06-22.md`) found auto_LiRPA
rejecting both `onnx::Less` branch predicates of the exported `erf64.onnx`
before GenBaB could run. The 2026-07-10 probe
(`experiments/abcrown-probe-2026-07-10/`) completed the run: the rejection
reproduces on release 0.7.0 but is fixed by a ~40-line
`register_custom_op` bound for `Less` (no fork; since hardened with a
fail-closed soundness suite), after which stock input-split branch-and-bound
verifies price ∈ [0, 20] in 1.06 s (66 domains) and the near-exact
price ∈ [8.0, 13.2] in 1.33 s (194 domains), float-computed. Beacon proves
the same [0, 20] goal with Arb certification in its own test suite, so the
cross-engine differential agreement this plan's validation track called for
now exists. The unsupported-op finding was real but shallow; it is not a
justification for in-house branch handling. The durable justification is
checkability: Beacon's verdicts are certified, the external tool's are
float-computed, and the two must never carry the same label.

The 2026-07-13 hard-claims round (`experiments/hard-claims-2026-07-13/`)
measured where each engine is the right choice: the hybrid
searcher-plus-Arb-certifier is ~150× faster at 1-D, at parity on loose 3-D
range goals, ~3× slower on the tight 3-D goal (while returning the stronger,
certified verdict wherever it finishes), and capped out with no verdict on
the NN-composed claim that alpha-beta-CROWN verified in 159 s. The division
of labor is therefore measured, not asserted: the scalar fragment stays in
Beacon; NN-composed goals and tight goals over higher-dimensional boxes go
to the rented searcher behind the chelis dispatch seam (roadmap 4.1); and
the verdict-upgrade wrapper (roadmap 4.3) re-certifies the rented searcher's
input-split decompositions leaf-by-leaf with Arb, so even those verdicts can
graduate to the certified class where the wrapper applies.

**Luna.** Luna is found and identified: "The Luna Bound Propagator for
Formal Analysis of Neural Networks", arXiv:2603.23878 (LeCates and Wu) — a
C++20 α-CROWN library, BSD-3-Clause, that links against standalone libtorch
with no Python interpreter (roadmap Appendix A has the full findings and
candidate table).
Decided already: Luna's existence softens but does not eliminate the
form-factor argument (the libtorch runtime remains), and it changes nothing
about this plan's structure — under own-the-checker/rent-the-searcher it is
a candidate rentable searcher whose decompositions the Arb kernel would
re-certify exactly as roadmap 4.3 does for auto_LiRPA. Open: the evaluation
spike, roadmap item 4.4, still pending — confirm the no-Python link path and
artifact size, and probe the op gap (Luna currently lacks the `Less`/`Where`
ops our branch graphs need, so adoption means a custom-op path or an
upstream contribution). Its outcome lands as an addendum to the decision
record.

## 5. Work items

The WI-B series is this plan's own numbering; master-plan WI-1..WI-14
references are to `spec/design/verification_stack_master_plan.md` (chelis).
The WI-H series belongs to the decision record and is scheduled as roadmap
Phase 2. Status below is the truth on this branch today.

**WI-B1 Interval forward stage.** Shipped: interval-domain forward
propagation over the RISC DAG with the standalone CLI lane and soundness
testing.

**WI-B2 Per-op transformer corpus.** Shipped for the scalar-elementwise
surface: `Add`, `Mul`, `Neg`, `Exp`, `Log`, `Sqrt`, `Div`, `CmpLt`, `Cast`,
`Recip`, `MaxElem`, `Abs`, `Sin`, `Cos`, `Tan`, `Atan`, `Floor`, `Ceil`,
with domain preconditions (`Recip`/`Div` exclude zero, `Tan` excludes
poles) failing closed. Tensor/shape ops remain `unsupported` pending the
beacon#52 decision.

**WI-B3 Zonotope domain.** Shipped as an internal domain plus the
zonotope-verified proof lane: provenance-aware joins that preserve
common-input symbols and hull residuals, affine-plus-remainder nonlinear
transformers with interval-hull fallback, and Arb leaf certification as the
proof authority. Open: op parity with the interval lane (roadmap 2.7 —
enumerated-coverage oracle), high-dimensional zonotope union beyond the
common-provenance join, and shared-symbol relational-claim mode (roadmap
2.7, the analytic answer to the measured 1/margin splitting cost).

**WI-B4 Linear relaxation — re-scoped by the decision record.** No CROWN
backward pass is needed or planned for the scalar/finance fragment. The
re-scoped item is: tensor-aware abstract state first (pending beacon#52);
linear relaxation on top only if a consumer demands it. Tensor-scale goals
route to the external engine (alpha-beta-CROWN / auto_LiRPA) through the
chelis dispatch seam in the meantime. The existing
`src/linear_relaxation.rs` groundwork stays private and unreachable, with
tests enforcing that, until a consumer exists.

**WI-B5 Perturbed-branch policy — superseded for the scalar fragment.** The
shipped predicate ladder (section 3.3) plus the WI-H3 hull-mask is the
branch policy this graph class needs; the experiments measured that input
splitting suffices and GenBaB-style branching is not required. A
relaxation-guided branching policy would only return with WI-B4's
linear-relaxation domain, and is de-scoped with it.

**WI-B6 Special-function relaxation wiring.** Shipped (section 3.4). Open:
the ±300 range policy (roadmap 2.9).

**WI-B7 / WI-B7a Soundness oracle and bounded Arb split oracle.** Shipped
(section 3.5).

**WI-B8 Dispatch integration.** Beacon side shipped (the #439 subprocess
contract, `protocol --json`, proof bundles). Open, chelis-side: production
registration and the documented end-to-end manual gate (roadmap 1.1),
range-goal syntax (roadmap 1.2), capabilities honesty (roadmap 0.2). Open,
both sides: current WireDag v6 acceptance, version negotiation, and the CI
tripwire (roadmap 0.1; chelis#708). The gradient-graph path for verified Greeks has chelis-side
plumbing (WI-10 fan-out) and no production caller.

**WI-B9 Standalone and neural-network path — re-scoped.** Beacon has no

## 6. The float-versus-real decision

Beacon bounds over the reals first, as the CROWN lineage and the reference
verifiers do; this is the standard first target and what the verified-Greeks
and verified-pricing-bounds story needs. Floating-point roundoff soundness
is a later, separate layer, surfaced through the `Cast` transformer: a
roundoff-aware cast transformer would model machine roundoff and make the
bound sound with respect to the executed floating-point program rather than
its real-valued idealization. Its cost is scoped against the real-valued
baseline once that baseline exists; until then, every Beacon discharge
carries a real-valued/no-roundoff note outside the qualifier set so the
composite never implies roundoff soundness it does not have. The IEEE-754
rounding model is tracked as a long-horizon item in the roadmap.
