# Dataset Sensitive Autotuning of Multi-Versioned Code based on Monotonic Properties

## Metadata
- **Authors:** Philip Munksgaard, Svend Lund Breddam, Troels Henriksen, Fabian Cristian Gieseke, Cosmin Oancea
- **Venue/Year:** Not explicitly stated in the provided excerpt (DIKU, University of Copenhagen)

## Summary
This paper addresses the challenge of selecting optimal code versions from a compiler-generated pool of semantically equivalent but differently optimized implementations. In functional languages like Futhark, aggressive rewrite-rule systems (e.g., incremental flattening for GPGPUs) produce multiple code variants that perform differently depending on dataset characteristics such as array dimensions and available parallelism. Static selection fails to adapt to these variations, while traditional black-box autotuners suffer from unpredictable tuning times, exponential search spaces, and unreliable results.

To overcome these limitations, the authors propose a deterministic, compiler-aware autotuning framework that exploits a monotonicity assumption in dynamic program properties (e.g., degree of exploited parallelism). Instead of relying on stochastic search, the tuner processes each training dataset independently, computes maximal valid threshold intervals for each code-version guard, and intersects them to find a globally optimal configuration. If no single configuration satisfies all datasets, the framework produces human-interpretable diagnostics rather than silently failing.

The approach is integrated into the Futhark compiler and evaluated on real-world applications and standard benchmark suites. It demonstrates that tightly coupling autotuning strategies with compiler transformation structures yields predictable, fast, and highly effective tuning. The method significantly outperforms OpenTuner-based baselines in both tuning efficiency and final runtime performance, highlighting the value of semantic-aware autotuning in high-performance computing.

## Key Contributions
- A deterministic, dataset-sensitive autotuning framework tailored for multi-versioned code generated by compiler transformations.
- Formalization of a **monotonicity assumption** for dynamic program properties, guaranteeing at most one performance crossover point per code-version branch.
- A bottom-up tuning algorithm that computes maximal threshold intervals per dataset and intersects them globally, ensuring optimality when feasible.
- Efficient handling of both **size-invariant** (O(1) runs) and **size-variant** (O(log n) binary search) dynamic properties within a unified framework.
- Empirical validation showing up to **22.6× faster tuning** and up to **10× better runtime performance** compared to stochastic black-box autotuners.

## Technical Approach
The compiler generates a **tuning forest** where each branch is guarded by a predicate `P_i ≥ T_i`. `P_i` is a dynamic property (e.g., parallelism level) known at runtime, and `T_i` is a threshold to be tuned offline. The core algorithm relies on the monotonicity assumption: if a guarded version `V_i` outperforms deeper versions at `P_i`, it will continue to do so for all larger `P_i` values.

1. **Per-Dataset Tuning:** For each training dataset, thresholds are initialized to `∞` to force execution of the deepest (most parallel) version, establishing a baseline runtime.
2. **Bottom-Up Traversal:** The tuner walks the tuning tree from leaves to root. At each threshold `T_i`, it runs the guarded version and compares its runtime to the best runtime found so far in the subtree.
3. **Interval Computation:** 
   - For **size-invariant** properties (constant `P_i` during execution), the optimal interval is computed in one run: `[0, P_i]` if the guarded version wins, or `[P_i+1, ∞]` otherwise.
   - For **size-variant** properties (`P_i` changes during execution), the tuner collects all unique `P_i` values and performs a binary search over them to locate the crossover point in `O(log m)` runs.
4. **Global Intersection:** Optimal intervals from all datasets are intersected. A non-empty intersection guarantees a threshold configuration that optimally discriminates versions across all training data. An empty intersection is reported deterministically, allowing developers to adjust code version ordering or introduce duplicates.
5. **Minimal Instrumentation:** Requires only lightweight compiler modifications to emit dynamic property values and execution times, making it portable to other multi-versioning compilers.

## Results
- Evaluated on 11 benchmarks (Heston, BFAST, LocVolCalib, and Rodinia/FinPar suites) on an NVIDIA RTX 2080 Ti GPU.
- **Tuning Time:** Achieved an average **6.4× speedup** (up to 22.6×) over a highly optimized OpenTuner baseline. Tuning time is deterministic and scales predictably with the number of thresholds.
- **Runtime Performance:** In 5 out of 11 cases, the tuned programs ran up to **10× faster** than OpenTuner-tuned versions. OpenTuner frequently converged to local minima, produced degenerate thresholds, or failed with out-of-memory errors on large datasets.
- **Reliability & Diagnostics:** The framework consistently found optimal or near-optimal thresholds. When no single configuration covered all datasets, it provided clear, actionable feedback (empty intervals) rather than opaque stochastic failures.

## Relevance
- **Compiler & Language Design:** Demonstrates the power of **compiler-autotuner co-design**. By exposing compiler-generated structure (tuning forests) and leveraging semantic properties (monotonicity), autotuning becomes deterministic, efficient, and interpretable. Highly relevant for functional/array languages (Futhark, Halide, Lift) that rely on multi-versioning or schedule selection.
- **ML Systems & Performance Engineering:** ML workloads often exhibit highly variable input shapes and batch sizes. This approach offers a lightweight, deterministic alternative to expensive ML-based or stochastic autotuners for dynamically selecting kernel implementations, parallelism granularities, or memory layouts based on runtime data characteristics.
- **GPGPU/Heterogeneous Computing:** Provides a practical solution for mapping nested or irregular parallelism to flat GPU hardware. The runtime overhead is minimal (simple threshold checks), making it suitable for production systems where predictable performance and fast offline tuning are critical.
