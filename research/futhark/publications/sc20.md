# Compiling Generalized Histograms for GPU

## Metadata
- **Authors:** Troels Henriksen, Sune Hellfritzsch, Ponnuswamy Sadayappan, Cosmin Oancea
- **Venue/Year:** SC20 (International Conference for High Performance Computing, Networking, Storage and Analysis), 2020

## Summary
Parallel histogram computations are ubiquitous in scientific computing, data analysis, and machine learning, but efficiently executing them on GPUs is challenging due to high bin-conflict rates and memory hierarchy constraints. While standard histograms only count occurrences per bin, many real-world applications require *generalized* histograms that apply arbitrary associative and commutative operators to values mapped to bins. Existing GPU libraries and compiler frameworks either lack support for generalized operators, rely on expensive sort-scan fallbacks, or require manual tuning of conflict-reduction strategies.

This paper introduces an adaptive GPU execution strategy for generalized histograms that dynamically balances bin-conflict rates and memory footprint. The authors develop an analytical model that automatically selects optimal multi-histogram (subhistogramming) and multi-pass parameters based on hardware characteristics, operator type, histogram size, and data sparsity. The technique is implemented both as a standalone CUDA library and as a first-class construct (`genhist`) in the Futhark parallel array language, complete with compiler-driven optimizations.

By elevating generalized histograms to a high-level language primitive, the work demonstrates that programmers can express irregular parallel patterns declaratively while the compiler and runtime automatically generate highly optimized GPU code. The approach eliminates the need for manual parameter tuning, supports arbitrary data types and operators, and seamlessly integrates with existing high-level frameworks, bridging the gap between productivity and performance on modern accelerators.

## Key Contributions
- Formalization of the **generalized histogram** as a high-level parallel primitive supporting arbitrary associative/commutative operators and value transformations.
- An **adaptive GPU execution strategy** combining multi-histogram (cooperative subhistogramming) and multi-pass traversal to balance thread conflicts and fast-memory capacity.
- An **analytical parameter-selection model** that automatically computes optimal multi-histogram and multi-pass degrees using hardware specs, operator type, and a lightweight sparsity estimator (race factor).
- **Compiler integration in Futhark** featuring type-driven atomic primitive selection, vertical/horizontal fusion rules, loop distribution for batched histograms, and vectorized operator decomposition.
- **Comprehensive empirical validation** showing consistent outperformance over CUB and competitive/superior results against hand-tuned CUDA/OpenCL application kernels.

## Technical Approach
The core technique navigates the time-space tradeoff between conflict-free execution and memory footprint using two complementary mechanisms:
1. **Multi-Histogram (Subhistogramming):** Instead of all threads updating a single global histogram, threads are grouped to cooperatively update multiple partial subhistograms using atomic operations. This reduces contention at the cost of increased memory usage and a final reduction step.
2. **Multi-Pass Traversal:** The histogram is processed in sequential passes over contiguous bin ranges. Each pass only loads a chunk of bins into fast memory (shared memory or L2 cache), enabling the technique to scale to arbitrarily large histograms.

**Atomic Primitive Selection:** The compiler/runtime statically selects the most efficient synchronization primitive based on the value type and operator:
- **HDW:** Direct hardware atomics (e.g., `atomicAdd` for integers/floats).
- **CAS:** Compare-and-swap (`atomicCAS`) for types ≤64 bits.
- **XCG:** Spinlock-based updates (`atomicExch`) for complex types or unsupported operators.

**Analytical Model & Sparsity Estimation:** The model computes the optimal multi-histogram degree ($M$) and pass count ($S$). For shared memory, it maximizes $M$ to fit within the available scratchpad. For global memory, it estimates histogram sparsity via a lightweight inspector that samples input elements to compute a *race factor* ($RF$). $RF$ is used to expand the effective L2 cache capacity, allowing higher $M$ for sparse data without cache thrashing.

**Compiler Optimizations (Futhark):** The `genhist` construct is integrated as a second-order array combinator. The compiler applies:
- *Vertical fusion:* Inlines `map` producers directly into the histogram kernel to avoid materializing intermediate index/value arrays.
- *Horizontal fusion:* Merges independent histograms sharing the same input array to reduce global memory traffic.
- *Loop distribution/interchange:* Extracts batched/segmented histograms from nested parallel code for efficient code generation.
- *Vectorized operator handling:* Decomposes vectorized operators (e.g., element-wise addition) into independent atomic updates per element, avoiding heavy spinlocks.

## Results
- **Model Validation:** The analytical model selects near-optimal $(M, S)$ parameters across diverse histogram sizes and sparsity levels, with a maximum slowdown of only **5%** compared to exhaustive static tuning.
- **vs. CUB Library:** Outperforms CUB's `HistogramEven` (HDW) by **3.1–32.7×** and CUB's sort-scan fallback (CAS/XCG) by **1.6–8.1×**, with larger gains for bigger histograms and sparse data.
- **Application Benchmarks:**
  - `435.gromacs` (SPEC CPU2006): Matches hand-tuned CUDA for HDW; achieves **2.65× speedup** for CAS.
  - `k-means`: Matches `kmcuda` for large $k$; up to **30.7× faster** for small $k$.
  - Parboil `histo` & `tpacf`: **4.7×** and **1.13×** speedups, respectively.
  - Image Registration (PyTorch vs. Futhark): Replacing PyTorch's sort-scan with `genhist` yields **132×–469×** speedups.
- **Overall:** The compiler-generated code consistently matches or exceeds hand-optimized implementations while requiring significantly less developer effort and providing cross-GPU portability.

## Relevance
- **Language Design:** Demonstrates the value of elevating irregular parallel patterns (histograms/reductions) to first-class language constructs. It shows how high-level abstractions can retain performance when paired with targeted compiler transformations, reducing the cognitive load on developers.
- **Compilers:** Provides a blueprint for automatic parameter tuning in GPU code generation. The fusion rules, atomic selection logic, and sparsity-aware analytical model illustrate how compilers can safely optimize irregular memory access patterns without programmer hints.
- **ML Systems:** Generalized histograms are foundational in ML workloads (e.g., gradient boosting/XGBoost, k-means clustering, locally orderless image representations, and histogram-valued data analysis). The work offers a drop-in, high-performance primitive that can accelerate frameworks lacking native support (e.g., PyTorch) and suggests how specialized constructs could improve automatic differentiation pipelines by avoiding low-level atomic bottlenecks.
