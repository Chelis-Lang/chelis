# Bounds Checking on GPU

## Metadata
- **Authors:** Troels Henriksen
- **Venue/Year:** Not specified in the provided text

## Summary
This paper presents a compilation strategy for safety-checking array indexing in high-level languages on GPUs. The technique does not rely on hardware support for abnormal termination and is designed to be efficient in the non-failing case. The approach leverages properties of array languages, such as the absence of arbitrary cross-thread communication, to ensure well-defined execution in the presence of failures. The author has implemented this technique in the compiler for the functional array language Futhark and empirically evaluated it on 19 benchmarks, showing a geometric mean overhead of 4% and 6% on two different GPUs.

## Key Contributions
- A compilation strategy for inserting safety checks in GPU code generated by compilers for high-level parallel languages.
- The technique does not rely on support for abnormal termination or error reporting in the GPU API or hardware itself.
- The approach ensures completeness, efficiency, robustness, and quality of reporting for safety checks.
- Implementation of the technique in the Futhark compiler and empirical evaluation on 19 benchmarks.

## Technical Approach
The paper proposes a method to handle safety checks in GPU code by using a global failure variable to track failures. Each distinct failure point in the program is assigned a unique failure code, and when a failure occurs, the corresponding failure code is written to the global failure variable. The technique also includes optimizations to reduce the overhead of failure checking, such as avoiding unnecessary global memory accesses and synchronization points. The approach ensures that the GPU driver context remains operational even in the presence of safety check failures.

## Results
The empirical evaluation on 19 benchmarks shows that the geometric mean overhead of checking array indexes is 4% and 6% on two different GPUs. The results demonstrate that the overhead of bounds checking is relatively modest, making it feasible to perform bounds checking by default even in high-performance array languages.

## Relevance
This paper is relevant to language design, compilers, and ML systems work because it addresses the challenge of implementing safety checks in GPU code generated by compilers for high-level parallel languages. The technique presented in the paper can be applied to improve the safety and reliability of GPU-accelerated applications, particularly those written in functional array languages. The approach also provides insights into optimizing the performance of safety checks in GPU code, which is crucial for maintaining high performance in parallel computing environments.
