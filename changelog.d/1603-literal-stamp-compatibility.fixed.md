`vmap`'s axis child and `tuple-get`'s index child are now visited by type inference, so a literal whose declared type stamp contradicts its atom -- such as `(lit {type: (t-prim {} bool)} 1)` -- is rejected there with the same atom/primitive diagnostic every other literal position already emits. Previously both forms read the integer out of the literal without ever admitting it, so the stamp was ignored and no diagnostic was reported. Bare integers and `int32`- or `int64`-stamped integer literals are unaffected. See [#1603](https://github.com/Chelis-Lang/chelis/issues/1603).
