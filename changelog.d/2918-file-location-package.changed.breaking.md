Every command now decides which reef package a file belongs to by walking up from the file itself; the directory the command runs in no longer matters. `chelis eval --file` used to evaluate a file with no `module` declaration in the package containing the current directory, so the same file could import a package's modules from one directory and not from another, while `check` and `build` rejected every file inside a package that was not one of its modules. A file that lies inside a package but outside its source roots, with or without a `module` declaration (a script beside `reef.toml`, a test under `tests/`), is now an entry of that package in `chelis eval`, `check`, `build`, `cost`, and `prove` from any directory, as it already was for `chelis test`; a file with no `module` declaration outside every package cannot import a package's modules even when the command runs inside one. `chelis test PATH` likewise takes its package from `PATH` and no longer falls back to the current directory's package, and it refuses a discovered file that belongs to another package, such as one nested under `PATH` with its own `reef.toml`, instead of running it in the wrong one. `chelis prove --package DIR` still links a file with no `module` declaration into the package at `DIR`, and now rejects a file that declares a `module` when the file's own location finds a different package; it used to ignore the option for such a file. See [#2918](https://github.com/Chelis-Lang/chelis/issues/2918).
