A tensor operand whose precision is a type variable no longer escapes the operand-dtype family policy. A float-only operation reached through an unbounded precision binder, such as `mean` inside `def g[p](x: tensor[3, p]) -> tensor[p]`, checked clean when the instantiating call site passed a tensor literal, a nested call's result, or a top-level value binding, and the compiled C lane then printed the integer quotient. Those instantiations are now rejected where the call site supplies the dtype. A binder that declares a dtype-family bound is decided at its definition, and a precision that binds one application later is decided when it binds.
