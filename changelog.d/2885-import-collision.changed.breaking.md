A module that both imports a name into unqualified scope and declares it at top level is now rejected by `chelis eval`, `check`, `build`, `cost`, `prove`, and `test` alike, with a diagnostic naming the import and the local declaration: `import Std.Scalar (max)` or `import Std.Scalar (..)` beside a local `def max` no longer compiles, in a package module or a file with no `module` declaration. Previously `chelis eval` used the imported binding while `check` and `build` used the local one, so the same program printed different results. Rename the local declaration, or import the module qualified (`import Std.Scalar`) and write `Std.Scalar.max`; parameters and local bindings may still reuse an imported name. See [#2885](https://github.com/Chelis-Lang/chelis/issues/2885).
