A local tensor ascription may name a dimension parameter that only the
declared result mentions, such as `step1: tensor[c, h, f32] = insert(v, 1i32,
h_dim)` in a function returning `tensor[c, h, w, f32]`. The first site that
produces the extent binds the parameter for the rest of the invocation, and
every later site naming it, including the declared result, traps `Domain` on a
mismatch. This holds on every path through a runtime `if` or `match`, on both
`chelis eval` and compiled C. Lowering used to refuse the ascription on both
lanes with "cannot resolve authored extent". In a function body with runtime
control flow, a local ascription naming a parameter's dimension is now also
checked at its own producer by `chelis eval`, as compiled C already did; inside
a lambda body `chelis eval` still refuses it. A site naming a binder that
only the body names, or that only a `List` parameter's element type names, is
still refused. See
[#2937](https://github.com/Chelis-Lang/chelis/issues/2937).
