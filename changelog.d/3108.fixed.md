`chelis lint` no longer re-runs the full typed pipeline on a whole file for
every `prefer-pipe-operator` or `redundant-linearity-call` candidate. The
pipeline check is a necessary guard on these rewrites, not a proof that they
preserve meaning (that question is open in
[#3119](https://github.com/Chelis-Lang/chelis/issues/3119)). It now declines a
rewrite unless the pipeline accepts both the original and the rewritten
source, and computes the original's verdict once per distinct source text. A
file the pipeline rejects therefore costs one run per lint pass, however many
candidates it holds. `chelis lint --check .` over this repository falls from
about 59 s to about 1-2 s (release build). The new `chelis lint --stats` flag
reports each file's candidates, pipeline runs, and the original's verdict as
JSON lines on stderr.

Behavior change: a rewrite of a source the pipeline rejects is no longer
offered. For example, the old gate offered to strip `drop` from
`def f(w: tensor[2, f32]) -> tensor[2, f32] = drop(realize(w))`, which turned
an ill-typed program into a well-typed one with a different meaning. See
[#3108](https://github.com/Chelis-Lang/chelis/issues/3108).
