`chelis lint` no longer re-runs the full typed pipeline on a whole file for
every `prefer-pipe-operator` or `redundant-linearity-call` candidate. A fix is
offered only when the pipeline accepts both the original and the rewritten
source, and the original's verdict is computed once per file, so a file the
pipeline rejects costs one run however many candidates it holds. A strip that
would turn a rejected program into an accepted one is no longer offered. Files
are also checked in parallel, with output identical to a serial pass.
`chelis lint --check .` over this repository falls from about 59 s to about
1 s (release build). See [#3108](https://github.com/Chelis-Lang/chelis/issues/3108).
