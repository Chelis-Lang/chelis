The lint's shipped traversal policy no longer prunes inside a reef package's
declared source roots. Its patterns are gitignore-style and so matched at any
depth, while the reef loader applies no such filter: a `.ch` file under
`src/target/` was compiled by `chelis reef build` and invisible to
`chelis lint --check`, which reported success on a package that does not load.
Every shipped pattern was affected, not only the build-artifact names. Beneath
a source root those names are source, so the baseline stops pruning there. A
repository `chelis-lint.toml` entry is a deliberate local declaration and
continues to prune inside a source root, which is what excluding generated
`.ch` needs. The exemption is granted only by a manifest reef could build
from: `additional_sources` is validated as reef validates it, and a symlinked
`reef.toml` grants nothing, so a manifest the loader rejects or one outside the
lint's policy root cannot widen the lint corpus. See
[#2768](https://github.com/Chelis-Lang/chelis/issues/2768).
