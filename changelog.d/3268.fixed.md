`chelis build` for C, HIP and Metal now rejects a call through a function value that a `match` pattern projected out of a constructor payload, a record field, an `Option` or a tuple. The rejection is the typed `unsupported:` diagnostic that names the C target and cites [#879](https://github.com/Chelis-Lang/chelis/issues/879). Previously the build failed inside ownership lowering with a message naming a compiler-generated binder such as `__chelis_pattern_h__inl1`. `chelis eval` still runs these programs. A pattern that binds a function-valued scrutinee directly (`match f with { | g => g(x) }`) still fails with an internal host site-map error tracked by [#3027](https://github.com/Chelis-Lang/chelis/issues/3027). See [#3268](https://github.com/Chelis-Lang/chelis/issues/3268).
