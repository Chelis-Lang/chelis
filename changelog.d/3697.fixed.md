`chelis prove`'s fuzz tier spends part of its sample budget pairing binders
from *different* magnitude classes, so it no longer reports a passing
empirical verdict for a multi-binder property that fails at a pair of
representable inputs its guards admit. A property claiming `x / y` is finite
for positive `x` and `y` previously passed at every sample count; the tier now
refutes it with a large `x` and a subnormal `y`.

Each binder's edge inputs were indexed by the run's attempt ordinal, which is
shared, so binders with equal ranges took the same input at every attempt and
only ever met on the diagonal of the grid of possible pairs. For a property
with two or more binders, half the attempts now propose a cell of an odometer
over each binder's extremal classes instead: its interval's extremes, the
values nearest zero from each side, a zero its guards admit, and the input
nearest `1.0` in magnitude. Those are the binder's own edge inputs, so no new
input is proposed and the guards still admit every pair the tier reports.

The pairings do not depend on the seed, so a property refuted at one is
refuted under every seed. A single-binder property is unaffected. Because the
diagonal now advances every second attempt, a multi-binder property refuted
only at a late edge input needs about twice the samples; the default budget
still reaches every one of them.

See [#3697](https://github.com/Chelis-Lang/chelis/issues/3697).
