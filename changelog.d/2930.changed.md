The chelis-std runtime each compiler embeds is packed from `packages/chelis-std` while the compiler builds, and nothing generated from it is committed: the `packages/chelis-std/dist/` and `crates/chelis-std-bundle/dist/` pairs, `packages/chelis-std/reef.lock`, and `scripts/regenerate_chelis_std_bundle.py` are gone, and editing a std source and rebuilding the compiler is the whole workflow. CI refuses a tracked file under either `dist/` directory and a tracked `reef.lock` that records the bundled runtime. A Chelis checkout therefore carries no built chelis-std pair, so `chelis reef install --from-monorepo` of a checkout needs `chelis reef build packages/chelis-std` first; the bundled runtime itself needs no install, because every compiler serves it. `chelis-reef` and `chelis-compiler-api` take the runtime as an explicit `&'static EmbeddedRuntime` parameter. See [#2930](https://github.com/Chelis-Lang/chelis/issues/2930).
