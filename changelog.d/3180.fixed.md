A `drop` whose operand has a borrowed type where the call is checked, such as `drop(&x)` or a `drop` of a borrowed parameter, is now a type error naming the expected owned value, as [05-OP-67] requires. It was accepted and consumed nothing. A borrow that reaches `drop` through a type parameter, such as a generic function or a lambda applied to `&x`, or through `drop` used as a value, is not yet refused. See [#3180](https://github.com/Chelis-Lang/chelis/issues/3180).
