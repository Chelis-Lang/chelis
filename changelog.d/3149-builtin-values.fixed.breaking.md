A builtin is now a function value only when its whole operation contract travels with the value. That covers builtins whose type scheme states the contract completely (the pointwise arithmetic and float functions, the monomorphic string and file builtins, `drop`, the test assertions, the clock reads) and builtins whose scheme carries their operand/result relation (`len`, `index`, `append`, `concat`, `fold`, `scan`, the key builtins). Every other builtin is applicable only by name. Binding it (`op = sum`), passing it as an argument or as a `map`, `fold`, `vmap` or `grad` callback, placing it in a list or tuple, or returning it is now a `TypeMismatch` that names the builtin and suggests an explicitly typed lambda that calls it. Such programs previously passed `chelis check` with result types the operation never produces, for example an aliased `sum` declared to return `i8` or an aliased `lt` declared to return `f32`. A builtin named as a value now also performs its call's effect, so an alias of `read_file` or `test_assert` can no longer shed `IO` or `Test`. See [#3149](https://github.com/Chelis-Lang/chelis/issues/3149).
