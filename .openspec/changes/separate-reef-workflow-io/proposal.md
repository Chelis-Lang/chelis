## Why

`chelis-reef` and its conformance integrations combine deterministic manifest, lockfile, dependency, pin, origin, linking, and reconciliation policy with environment discovery, filesystem reads and writes, registry traffic, credentials, subprocesses, locking, and direct reporting. This makes policy hard to replay and allows adapters to participate in decisions that should remain canonical.

## What Changes

- Define immutable local/project/package snapshots and resolved non-secret host configuration as explicit workflow inputs.
- Model decision-bearing filesystem, registry, package-byte, credential-reference, process, and lock observations through a closed typed request/observation protocol.
- Give downloaded or generated bytes explicit content-addressed blob ownership so final plans never depend on ambient temporary paths or mutable buffers. Pure inspection receives immutable bytes or deterministic chunks before a reference is promoted to verified planning input; adapter metadata alone is never trusted as package content.
- Produce a closed local mutation plan only after every decision-bearing observation is available and validated. Model irreversible remote publication separately as an idempotent remote action plan rather than claiming local transaction rollback.
- Validate the whole local plan before execution, then acquire locks in a canonical scope/order, revalidate prerequisites under those locks, and execute transaction states fail-closed with atomicity stated per package root or artifact rather than implied across unrelated paths.
- Keep semantic workflow decisions separate from execution reports without introducing speculative workflow-result caching; remote publication alone receives a canonical body digest used to derive its idempotency key.
- Return structured notices, diagnostics, plans, and reports instead of printing from library decision or executor code.
- Apply the same snapshot/workflow/planning boundary to `chelis-conformance` audit, init, sync, and bump policy rather than leaving its direct repository reads as an FCIS bypass.
- Preserve public command behavior, package/lock formats, documented atomicity scopes, idempotency, and security. The independent prerequisite `require-explicit-reef-credentials` owns the approved removal of implicit `gh auth token`; this workflow change preserves and regression-tests that explicit-credential contract.

## Capabilities

### New Capabilities

- `tooling-action-plans`: Defines pure Reef/conformance workflow decisions, content-addressed plan inputs, and explicit transactional executors.

### Modified Capabilities

None.

## Impact

The change affects `chelis-reef`, `chelis-conformance`, their CLI call sites, setup orchestration, credential behavior, package/security tests, and machine output. It is independent from the lint snapshot change. Delivery remains command-family scoped, with named focused gates for read-only analysis, local install transactions, conformance repair, source wiring, and remote publication; no family is complete while policy-bearing direct host access remains in its designated decision modules, and focused green evidence does not replace the final oracle. After the standalone `establish-dylint-tooling` oracle passes, `establish-fcis-contract-mechanics` registers stable coverage IDs, exact workflow bounds/result projection, typed blob/plan/vocabulary owners, the command-family matrix and cross-slice invariant, prerequisite edge, boundary/threat model, and fail-closed slice/final oracles.
