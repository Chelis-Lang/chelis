## Current routing

- [CI workflow](https://github.com/Chelis-Lang/chelis/blob/71815c2802b96767577fdc0144aab5de68535f77/.github/workflows/ci.yml#L1113-L1458): ordinary code PRs run `Fast Tests (Linux)` (`chelis-gate ci-fast`), plan changed integrations, execute four required change-owned shards, and validate their report. Main pushes run the fixed fast selection only. Empty shards skip build setup. All ordinary PR jobs use `ubuntu-latest`; exact trusted dispatch can choose reviewed warm runners.
- [Fast selector](https://github.com/Chelis-Lang/chelis/blob/71815c2802b96767577fdc0144aab5de68535f77/scripts/ci_test_targets.py#L156-L280) runs all default-feature lib/bin units plus the `.config/ci-test-targets.toml` standing integration targets. It builds workspace products, lists, then runs nextest groups without the default filter, and seals selected/executed test evidence.
- [Planner](https://github.com/Chelis-Lang/chelis/blob/71815c2802b96767577fdc0144aab5de68535f77/scripts/ci_change_owned.py#L1430-L1712): added/directly modified integration targets and all targets promoted by `required_package_rule` enter `change_owned`; other eligible targets in selected packages enter `package_expansion`. These sets are disjoint. A standing target in `change_owned` is removed from required shard execution only after the report authenticates the same-candidate fast receipt. [Manual workflow](https://github.com/Chelis-Lang/chelis/blob/71815c2802b96767577fdc0144aab5de68535f77/.github/workflows/pr-package-expansion.yml#L24-L210) runs the expansion set on explicit exact-head dispatch, independently of the required CI verdict; it classifies introduced/inherited failures and unrun targets against the eligible nightly baseline. [Operational contract](https://github.com/Chelis-Lang/chelis/blob/71815c2802b96767577fdc0144aab5de68535f77/docs/ci_validation.md#L1-L30), [selection detail](https://github.com/Chelis-Lang/chelis/blob/71815c2802b96767577fdc0144aab5de68535f77/docs/ci_validation.md#L269-L315).
- Heavy full-workspace, feature and hardware coverage remains scheduled/manual in `heavy-e2e.yml`, `macos-nightly.yml`, and other owner workflows. Required CI's rust-policy job runs Clippy/doctests/compile guards rather than a second whole-workspace nextest pass. Backend Sanitizers deliberately repeats `chelis-backend-c` lib units under ASan/UBSan (`ci.yml:1539-1544`), a different configuration. The docs' historical “unfiltered cargo test” sentence in `scripts/gate.py:151-152` is stale: workflow now says `--lib` and `--doc` separately.
