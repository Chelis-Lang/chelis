## Mechanism and coverage

Five extent matrices compile identical exported Chelis definitions again for different runtime input dimensions. The candidate reuses a linked `-O2` C executable only inside one matrix test invocation, keyed by the exact generated C (including the caller), sealed generated header, resolved C toolchain settings, and the staged runtime receipt (archive and public-header hashes). It checks every fresh build's receipt against the first. The caller reads exact `f32` bits and dimensions from argv, then invokes the same exported ABI. A cache hit still runs a fresh C process. Every case still runs its own `chelis check` and `chelis build`; binding and root routes still run evaluator and independently compiled C, with their original per-case result/trap assertions. No result verdict, CI target selection, or cadence is reused or changed.
