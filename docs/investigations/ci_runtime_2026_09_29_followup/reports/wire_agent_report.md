## One narrow change worth a PR

**Reuse the already-built `wire_publication_probe` for the selected local-publication mutation controls.** The schema's `--examples` command (`capacity_census_wire_adapters.py:1064-1085`) builds that probe in `target/agents/729-capacity-rustdoc`, and `capacity_census_wire_schema.py:1811-1819` runs `build_probe` again there. The main-target `cargo build --example wire_publication_probe` took **3.65 s** in the named trace. The later supervised Python selection includes `LocalPublicationControls` (`capacity_census_wire_acceptance.py:130-141,253-256`), whose `setUpClass` instead invokes `build_probe` at `target/agents/wire-codec-rustdoc` (`scripts/test_capacity_census_wire_local.py:14-20`): the *same probe build* took **168.56 s** in that second target. Its fixture `cargo rustc` expansions also use `self.target` (`:22-64`); leave those in their existing separate target. The fixture rustdoc mutation target `target/graph-fixture-target` is another independent source-mutation proof, not this duplicate build (`scripts/test_capacity_census_wire_publication.py:218-331`).

In `scripts/capacity_census_wire_runner.py:366-409`, add an optional, validated worktree-local probe-target argument to `run_python_tests` and pass it only for the mutation selection from `execute_acceptance_controls`. Route it through the supervised subprocess environment. In `scripts/test_capacity_census_wire_local.py:14-20`, use that target **only** for `build_probe`; keep `self.target` for fixture expansion and standalone test runs. Reject an override outside this worktree's `target/`, and continue calling Cargo to select the probe and executing every positive/negative control. The main target is held by the verifier and is idle while the synchronous supervisor runs; the schema has already built this current-source binary before acceptance (`capacity_census_wire_verifier.py:122-131`). Keep the codec clean, source-byte validation, baseline comparison, cache seal, and separate invocation target exactly as they are.

## Shard combinations

Do **not** combine wire with bindings to seek this saving. `scripts/capacity_census_compiler_json.py:345-390` calls `verify_wire_census` *inside* the binding proof and then performs its own conversion and compiled authority work. `VerifiedWireCensus` cannot be reconstructed from another shard's JSON; two parallel hosted shards also lack a shared target. Putting both tests on one runner serializes two full proofs. The binding scopes already share their own dependency target (PR #2685), while wire invocation remains independent (`scripts/capacity_census_wire_calls.py:781-806`). Nor does combining with runtime extents remove execution: `scripts/runtime_extent_oracle_targets.json:124-152` selects the whole wire test as a separate phase-A receipt. Co-location adds a long serial obligation unless a different, source-bound in-process ownership contract is designed and measured. Leave PR expansion's parallel shard selection intact.

**Recommendation:** Make the probe-target routing the next focused PR. Do not change the test selection, C6 authority path, cold-source rebuild, or CI cadence. Measure the complete selected wire case and shard critical path before claiming a hosted wall-time gain.
