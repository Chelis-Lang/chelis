## Decision

**A lockfile text diff or a semantic package-record diff alone cannot safely narrow expansion.** The current planner's `cargo metadata --no-deps --locked` supplies workspace manifests and integration targets, but `resolve` is null, so it cannot map a changed external package through resolved versions, aliases, optional features, platform dependencies, build dependencies, and proc macros (`scripts/ci_change_owned.py:2838-2865`; Cargo Book, *cargo metadata*, “OUTPUT FORMAT”). Its workspace-only reverse closure at `:669-708` is insufficient for that job and uses only the candidate graph.

There is also a real **byte-sensitive global input**. `crates/chelis-runtime/build.rs:113-130` hashes the complete root lockfile into `build_record.txt`; `crates/chelis-runtime/src/build_record.rs:15` exposes its digest through `SOURCES`. Thus a lockfile re-serialization changes the runtime build output even when the parsed package records are identical. The runtime and its reverse workspace closure must be seeded on **every** root-lock byte change, and `chelis-runtime-bundle` remains required. The present lock graph puts 13 workspace members, including `chelis-cli`, in that closure. `crates/chelis-runtime/tests/element_contract.rs:126-147` also copies the root lockfile into a compile fixture. Nix and Python checks read it separately (`nix/ci-arb.nix:7`, `nix/source.nix:10-12`, `scripts/capacity_census_wire_calls.py:575-578,635-638`); their job ownership must survive any package-lane change. Cargo's graph alone cannot discover arbitrary file reads in a build script or test.

**A conservative narrowing is possible after a direct-reader inventory and guard, but an *exact minimal* affected-package set is not proven today.** Recommend one focused **shadow-plan PR** that emits proposed selection and reasons while the enforced 35-package rule stays intact. Promote it only after the controls below pass; an unknown reader or unresolved graph retains the broad selection or errors loudly.

## Proposed mechanism and proof

In `generate_plan` (`scripts/ci_change_owned.py:2947-2976`), read each exact commit's `Cargo.lock` bytes and obtain **full** `cargo metadata --format-version 1 --locked --all-features` for both trees in `metadata_at`'s isolated checkout. Do not filter platforms; the metadata resolve graph then includes target-specific dependencies. Assert all workspace members are feature-selected; otherwise union per-member graphs. The all-features graph must cover each existing `target_features` command (`:1701-1703,3040-3078,3525-3538`), which keeps its current feature set. Assert every workspace member and every parsed lock package maps unambiguously to a full-metadata package; compare canonical package `(name, version, source, checksum, dependency entries)` and resolved edges/features, rather than line ranges or names alone. Cargo calls source IDs opaque, so do not equate textual source spellings without validating the mapping. Canonicalize local package IDs without embedding temporary checkout paths.

Seed changed package identities **on both sides**, traverse reverse `resolve.nodes[*].deps[*].pkg` edges including renamed, removed, dev, build, proc-macro, optional, and platform edges, and retain candidate workspace packages reached from either side. Union this with existing directly changed/added target routing, package path rules, byte-sensitive runtime closure, and registered lockfile readers. A workspace version change or a changed package dependency list is a seed even if no external version moves. Parsing-identical lock byte changes are labeled “re-serialization,” with zero dependency seeds **but still the byte-sensitive seeds**. Preserve the required runtime-bundle promotion and plan digest/receipt coverage. On a later enforcing change, replace only the `Cargo.lock` expansion disposition in `make_plan` (`:1480-1645`), record base/candidate graph digests and closure reasons in the plan, and update `_validate_plan_shape` (`:2026`) and `verify_plan_digest` (`:2407`) plus `scripts/test_ci_change_owned.py`.

Negative controls must show: two same-name versions with distinct sources; checksum-only replacement; added and removed dependencies or workspace members; rename across dependency kinds; a target enabled only by `required-features`; target-specific, build-script, proc-macro, and dev edges; a formatting-only lock edit still selecting runtime closure and required bundle; and a new direct lockfile reader rejected until registered. Malformed/unknown lock schema, missing candidate object, `--locked` resolution failure, unmapped ID, missing graph edge, or unsupported reader attribution must never produce a narrowed plan. A bare `git diff Cargo.lock` is no oracle.
