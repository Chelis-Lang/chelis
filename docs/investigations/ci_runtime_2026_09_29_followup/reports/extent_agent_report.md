# Runtime extent test restructuring audit

**Scope and head.** Read-only assessment at `465a3623be19bd68ada6c39aa7552b63e0ccf8c3`. The brief's timing, PR-frequency, and September 29 overlap figures are treated as supplied evidence, not recalculated. No build or CI was run for this report.

## What can share work

A shared **observation** table is feasible for the public runtime cases: identify a case by exact source, activation form, runtime inputs, target/toolchain and environment; record check status and inferred signature, Eval output, C build/link/execute status and emitted code. Apply separate assertions to the observation for exact tensor bits/shape, checker errors, guard trap and operation name, source/axis/value context, first failure, effect count, emitted order, and lane agreement. Collect failures by case and obligation rather than letting one successful parity comparison certify everything. The existing `Case`/`Expected`, `contract_failures`, and accumulating `collect` in `runtime_extent_claim_preparation.rs:24-48,846-1037` already implement part of this model.

Keep each discriminating source and execution independent. `runtime_extent_slice_b.rs:755-844` places a runtime divide-by-zero before *and* after a mismatching `insert` claim; either half alone misses a wrongly moved guard. Its effect pair at `1341-1400,1553-1661` checks visible output and emitted C placement. The rank/admission checks at `8871-8928` call one exported function with malformed ranks and distinct extents; collapsing to an ordinary source-level call would let the checker reject before the ABI guard. Entry-witness tests at `8689-8869`, producer/source tests, mapped-gradient controls at `9270-9398`, and IR derivation/rebuild receipts in `runtime_extent_slice_b_classes.rs` distinguish mechanisms a single “both lanes failed” bit cannot. Preserve ordered signature witnesses, scoped activations, matching controls, untaken invalid arms, and exact trap attribution. `spec/04-type-system.md` §4.7 fixes once-only guard execution, readiness, entry/signature and local/source order, and context; `spec/05-risc-primitives.md` §2.4.1 fixes runtime bound admission; `spec/06-transformations.md` §§3.7,5.4 preserve shared bound execution and traps through transforms.

There is genuine duplicate work, with an important existing optimization. In `runtime_extent_claim_preparation.rs:487-574`, `ExportBinaryCache` already links once per exact generated source/header, BLAS toolchain and staged-runtime receipt, then starts a fresh process with the next input. `observe_host_lane` at `589-790` still performs a new `chelis check` and `chelis build` for each export case. Good/bad exported calls in `call_matrix` at `74-107` use the same definition, so one checked source and one generated artifact could serve both runtime inputs while each gets a fresh ABI admission/execution receipt. Binding/root forms embed literals in different source and exercise distinct lowering routes; sharing their binary by replacing them with export calls would drop those routes. In Slice B, `c_run_status` at `505-525` builds and links on each invocation, and several Eval/C tests use the same fixture in different test functions. Co-locating assertions for an exact source can remove repeated checks/builds while retaining separate Eval and C processes. Some tests already bundle several guarantees per build (for example `issue_1932_mapped_grad_entry_witness_matrix_executes_exactly_on_both_lanes`); duplicating these in a new mega-matrix adds cost.

The capacity censuses have different input universes and failure oracles. `capacity_census_tripwire.rs:4147-4163,4197-4375,4413-4449` enumerates published C headers, stdlib and prelude ADTs, then checks exact final authority against its baseline and `[05-OP-N]` atoms. The phase-A `wire.capacity_census` row selects the *entire* 18-test `capacity_census_wire` binary (`runtime_extent_oracle_targets.json:126-157`); its `discover()` verifies the live wire graph, codecs, admission/publication and receipt (`capacity_census_wire.rs:25-62`). The primary tripwire is not an extent-oracle target. A common runner may schedule both and reuse an authenticated wire receipt, but a shared extent case table cannot establish C ABI or wire discovery/authority. Keep each census's negative mutation controls and baseline distinct under `dtype_semantics.md` §C6.

## Re-sharding and PR coverage

The final oracle (`runtime_extent_oracle.py:3043-3072,3277-3345,3916-4050`) constructs manifest commands, deduplicates identical ones, runs them sequentially, requires exact per-test names and success, validates corpus/baseline/coverage, then executes source-mutation controls. The brief identifies 61 executing target commands plus controls, and one ignored-HIP inventory listing. Splitting targets across workers can shorten this serial portion. Splitting *inside* a test is a separate change: the 55-case `claimed_extent_contract` is one opaque test to Nextest, and splitting its good/bad exports across processes loses its binary cache. Nextest can parallelize newly exposed case tests, but each worker repeats Cargo/test setup and generated C builds/links unless cases stay grouped by exact compiled artifact. Ordinary `cargo test` runs one selected test binary with libtest threading; full-workspace Nextest isolates test processes. Target `all` receipt equality and the target-manifest Fast reader must be updated to accept a disjoint, complete shard union. Run mutation controls serially in a private checkout/target: they temporarily edit `axis_sources.rs`, `specialize.rs`, desugar/checker/lower/eval/C/compiler sources (`runtime_extent_oracle.py:3575-3887`), so concurrent readers or builds of that tree would invalidate results.

The supplied receipts do not prove a CI makespan win. A 678-second Slice B target sat on a shard finishing 9.6 minutes *before* another shard; removing it there changes no aggregate finish time if other work is fixed. In the 970-second receipt its shard led the next by only 3.9 minutes, bounding the ideal aggregate saving there to 3.9 minutes if all other work is fixed. The root was touched by 17/531 PRs, though CLI package expansion selects it more widely. The September 29 name overlap (662 identities) proves neither equal features, target, profile, environment, libtest/Nextest behavior, exact per-target success, nor oracle coverage. The wire test alone appears in the dtype job and phase-A oracle; its recorded JUnit time is a sum, and the oracle retains no per-target times. No current receipt proves duplicate-work wall time or optimal shard assignment.

A small **required PR smoke** is reasonable only with an explicit reduced claim: one exact public source plus matching and mismatching Eval/C executions and before/after trap-order controls can certify *those* cells on the candidate head. A warning should state `full runtime-extent oracle UNRUN on <candidate SHA>; last nightly <SHA/result>; smoke <selected identities/result>` and flag changes in the extent-sensitive paths. It cannot infer that unselected guards, ABI/wire census, rewrite mutations, named witness scopes, hardware execution or the entire 206-row phase-B corpus pass. If the smoke is the only PR requirement, complete class-oracle evidence is deferred until nightly on the merged head; that can discover a regression only after merge. Keep change-owned selection for affected mechanisms where feasible. The existing standing Slice B target and intentional Fast exclusion of preparation mean a new smoke must earn its added critical-path cost.

## Two PR candidates and exit criteria

1. **Fixture reuse, no assurance reduction.** Group same-source exported good/bad inputs within `claimed_extent_contract` under one check and generated C build; preserve fresh executions and separate per-case assertions. Leave distinct test identities intact. Instrument check/build/link/execution counts; require fewer checks/builds for grouped exports, the same independent executions, exact 55 preparation cells, all registered test identities, and stable trap/context/effect/ABI results. Run at least three paired hosted baseline/candidate trials on matched runner profiles; accept a median preparation-target reduction of at least 10%, with no more than 5% regression in CLI package-expansion makespan. Avoid another combined-initializer regression like the supplied PR #2683 prototype.
2. **Authenticated nightly scheduling and bounded PR smoke.** First shard whole manifest targets by package/cost; keep per-target command semantics or prove equivalent feature/target/environment and test isolation for reuse from full-workspace/dtype. Have workers emit head, clean-source/manifest/corpus digest, command/configuration, exact selected/executed/pass set, runtime/toolchain identity and logs. Aggregate fail closed on duplicate/missing/ignored/failed identities or mutation controls; keep standalone `--phase final` exhaustive. Put mutation controls in an isolated serial lane. If nightly uses a receipt mode instead of the literal C5 command, amend `spec/design/runtime_extents.md` C5 to define the equivalent completion command and the separate PR-smoke claim; update oracle self-tests, target manifest/Fast reader, CI routing and `dtype_semantics.md` §C6's custody description for shared wire evidence. No numbered semantic-spec amendment is needed if obligations stay identical. Keep the wire census's own authoritative command and mutation authority.

For PR 2, accept only on hosted receipts tied to each run's exact head, with **zero lost/duplicate/unrun required identities, unchanged exit classes and independent red-mutation failures**, plus exact configuration provenance. Record per-target compile/build/link counts, CPU time, worker time and aggregate finish. In at least three paired matched-runner baseline/candidate trials, require at least 10% lower median extent-job duration with no more than 5% total nightly makespan or CPU-time regression and no new package-expansion timeout. The current two timings and JUnit names cannot establish those outcomes.
