## Original Branch Plan

Original branch context:

What the spec says H1 delivers:

- ONNX protobuf parser to internal IR:
  `hydronnx::ir::Model`, `Graph`, `Node`, `Tensor`
- `chelis-hydronnx-inspect` CLI utility with inventory for inputs, outputs,
  operators, weights, and opset
- Tests covering happy-path inventory agreement and malformed-input diagnostics

Implementation plan from the original handoff:

1. Crate scaffold.
   Create `crates/chelis-hydronnx/` with `Cargo.toml`, `src/lib.rs`,
   `src/ir.rs`, `src/error.rs`, and `src/parser.rs`. Add it to workspace
   members and `workspace.dependencies`.

2. Internal IR types: `hydronnx::ir`.
   Define `Model`, `Graph`, `Node`, `Tensor`, `TensorData`, `DataType`
   (`f32`, `f64`, `i32`, `i64`, plus `Unknown` for unsupported types),
   `Shape` as a vector of `Dim`, `Dim` as `Static(i64)`, `Symbolic(String)`,
   or `Dynamic`, `Attribute` variants for float, int, string, tensor, and
   graph, and `OpsetVersion`. Do not use `Onnx` prefixes on public type names.

3. Error types: `hydronnx::error`.
   Define `HydronnxError` variants:
   `FileNotFound`, `FileCorrupted`, `NotValidOnnx`,
   `UnsupportedOpset { found, supported_range }`,
   `UnsupportedOperator { name, node_index }`,
   `UnsupportedDtype { dtype_name, node_index }`,
   `UnsupportedShapePattern { description, node_index }`,
   `WeightConversionFailure { tensor_name, reason }`, and
   `InternalInconsistency { description }`. Each variant should carry enough
   context for the error model in the spec.

4. Protobuf bindings.
   Use `prost` and `prost-build` with the ONNX `onnx.proto3` file fetched from
   the ONNX repository. Write `build.rs` to generate bindings into
   `src/onnx_proto/`. Generated types are internal only; the public API speaks
   `hydronnx::ir` types.

5. Parser: `hydronnx::parser`.
   Implement `parse_model(path: &Path) -> Result<ir::Model, HydronnxError>`.
   It reads bytes, decodes protobuf, validates opset versions `v11` through
   `v21`, walks graph nodes and initializers, maps proto types to IR types, and
   surfaces errors per the error model.

6. Inspect CLI.
   Add binary target `chelis-hydronnx-inspect`, for example
   `src/bin/inspect.rs`. It prints model name, opset version, file size,
   input/output names, shapes, dtypes, operator list, and weight tensor
   inventory with name, shape, dtype, and byte size. Output is human-readable
   text.

7. Tests: `tests/parser_tests.rs`.
   Happy path: a small ONNX model such as linear regression, generated by
   `tests/fixtures/gen_fixtures.py` and committed as
   `tests/fixtures/linear_regression.onnx`. Error cases: truncated file,
   unsupported opset, and custom op. Each error case asserts the specific
   `HydronnxError` variant.

8. Gate integration.
   Verify `cargo build --workspace`, `cargo clippy --workspace`, and
   `cargo fmt --all -- --check`. `scripts/gate.py` already runs
   `cargo build --workspace --all-targets`, so the crate is included once it is
   listed in workspace members.
